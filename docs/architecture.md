# Architecture

The repository holds three independent packages. Two of them form the API layer:

- **`lit-canon-api`** ([packages/api](../packages/api)) is the Node.js generator and
  CLI. It depends on Orval, TypeScript, Prettier and Jiti.
- **`lit-canon-fetch`** ([packages/fetch](../packages/fetch)) is the browser runtime
  that generated code imports. It has no dependencies.
- **`lit-canon-composition`** ([packages/composition](../packages/composition)) is the
  app composition layer over Lit, `@lit-labs/router` and `@lit/context`. Neither API
  package depends on it; [lit-canon.md](lit-canon.md) shows how they meet in an app.

## How generation works

1. The CLI parses `generate` or `check`, loads the TypeScript config with Jiti and
   resolves paths relative to it. Removed options (`features`, `queryAliases`) fail
   here.
2. `generate()` checks output ownership, reads the local OpenAPI JSON and collects
   operations by tag. Each tag is one resource. It validates names and supported
   parameters.
3. Orval generates a split fetch client for each tag in a temporary directory next
   to the output. The pinned Orval version determines the TypeScript shape the
   transformation expects; see [decision 0001](decisions/0001-orval-postprocessing.md).
4. The renderers rewrite the request functions to call `apiFetch`, then produce
   models, the `<resource>Keys` factory, query and mutation options and optional
   problem types. Export validation detects conflicting names, and Prettier formats
   the output. Every file starts with "Generated by lit-canon-api. Do not edit
   manually."
5. `check` compares the staged files with the existing client. `generate` checks
   ownership again and replaces the output. Preserved directories move into the new
   tree; replacement failures attempt to restore the previous client.

The root generated `index.ts` exports one namespace per resource. Each resource has
`models.ts`, `api.ts` and `index.ts`, with `queries.ts`, `mutations.ts` and
`problems.ts` added when needed. See the
[catalog output](../examples/catalog/generated/products/) for concrete files.

## Source map: lit-canon-api

`add-page` is a separate one-time application scaffold in
[scaffold-page.ts](../packages/api/src/scaffold-page.ts). It reads the existing
operation model and generated function inputs, requires explicit route bindings,
and writes editable application files outside API output. See
[decision 0002](decisions/0002-intent-prefetch-and-page-scaffolding.md).

| File                                                           | Responsibility                                                                |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| [index.ts](../packages/api/src/index.ts)                       | Public API: `generate`, `defineConfig` and the config types.                  |
| [config.ts](../packages/api/src/config.ts)                     | Configuration, generation options, result types and removed-option errors.    |
| [cli.ts](../packages/api/src/cli.ts)                           | `generate` and `check` commands, config loading and exit status.              |
| [generate.ts](../packages/api/src/generate.ts)                 | Orval orchestration, formatting, staging, checks and output replacement.      |
| [openapi.ts](../packages/api/src/openapi.ts)                   | Operation names, tag grouping and parameter validation.                       |
| [references.ts](../packages/api/src/references.ts)             | Local OpenAPI reference resolution.                                           |
| [operation.ts](../packages/api/src/operation.ts)               | Internal operation types shared by the renderers.                             |
| [render-api.ts](../packages/api/src/render-api.ts)             | Orval AST transformation, paths, query parameters and request bodies.         |
| [render-queries.ts](../packages/api/src/render-queries.ts)     | Key factories, query options with cancellation and object mutation variables. |
| [render-problems.ts](../packages/api/src/render-problems.ts)   | Problem response extraction and generated problem types.                      |
| [validate-exports.ts](../packages/api/src/validate-exports.ts) | Export collision detection.                                                   |
| [files.ts](../packages/api/src/files.ts)                       | File traversal, ownership headers and symlink rejection.                      |

## Source map: lit-canon-fetch

[packages/fetch/src/index.ts](../packages/fetch/src/index.ts) contains the whole
runtime: configuration and header functions, query and body serialization, response
parsing and `ApiError`.

## Source map: lit-canon-composition

[intent-prefetch.ts](../packages/composition/src/intent-prefetch.ts) handles intent
at the app root; [app.ts](../packages/composition/src/app.ts) shares route matching
and lazy loads with `app.prefetch`. The optional
[query.ts](../packages/composition/src/query.ts) subpath adapts shared query options
without adding a TanStack import to the core entrypoint.

| File                                                     | Responsibility                                                |
| -------------------------------------------------------- | ------------------------------------------------------------- |
| [app.ts](../packages/composition/src/app.ts)             | `createApp`: routes, guards, lazy loading, titles, scrolling. |
| [container.ts](../packages/composition/src/container.ts) | `provide` and eager provider resolution.                      |
| [page.ts](../packages/composition/src/page.ts)           | `definePage`.                                                 |
| [feature.ts](../packages/composition/src/feature.ts)     | `defineFeature` and layouts.                                  |
| [guard.ts](../packages/composition/src/guard.ts)         | Guards and `redirect`.                                        |
| [errors.ts](../packages/composition/src/errors.ts)       | Error messages, prefixed with `[lit-canon]`.                  |
